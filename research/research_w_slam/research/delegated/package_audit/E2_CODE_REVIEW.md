# E2 read-only implementation review

Reviewed `tools/e2_revisit.py` against `FINITE_PILOT_SUPPLEMENT.json`, `src/wslam/finite_bayes.py`, `src/wslam/factors.py`, and `src/wslam/information.py`. No execution, physical calls, edits to core code, or network. Parent retains mathematical/scientific judgment. Only actionable findings follow.

1. **[P1] Task-weighted trigger uses a different risk than the frozen tau.** `tools/e2_revisit.py:61-63` computes `.05 * oldrisk + .005**2`, where `oldrisk` comes from each method's previous approximate covariance. `FINITE_PILOT_SUPPLEMENT.json:23-25` specifies the reference target Bayes risk. Those differ after new data and can also differ between arms, so `TASK_WEIGHTED` does not execute the declared trigger. `QUALIFIED_REOPEN` later audits against the current reference risk (`tools/e2_revisit.py:149-153`), but that does not repair the task-only arm. Pass the declared current reference tau to the trigger and explicitly attribute any reference dependence/cost, or resolve the protocol mismatch before execution without silently relabeling the existing formula as the frozen rule.

2. **[P1] Input validation does not fail closed on the frozen bank/panel schema.** `tools/e2_revisit.py:80-91` checks only `completed == 2950`; it does not check `total`, matching bank/grid/observation `prior_id`, data shape `(2950,4,16)`, residual shape/finite values, normalized nonnegative prior, observations `(12,2,4,16)`, ID shape `(12,2,3)`, or frozen channel/acquisition metadata. In particular, `newmeans.reshape(N,-1)` at line 100 can reinterpret extra bank rows as extra channels and broadcast a one-port `y`, rather than rejecting a mismatched bank. The code loads the supplement at line 87 but does not compare the actual dimensions and hardcoded sequence against it. Validate these schemas and identities before allocating posterior arrays or consuming the bank; enforce completeness using both recorded counts and actual array dimensions.

3. **[P2] `ITERATIVE_LAYER_POINT` is permanently wall-frozen despite its iterative-layer label.** `tools/e2_revisit.py:115-117` selects the early wall group once; lines 129-133 restrict both this arm and `HARD_FROZEN_WALL` to that same group at every later time. The only difference is collapsing the conditional distribution to a point. This does not implement a wall-revisiting iterative layer baseline and may be read as a stronger alternative than it is. Rename it to an explicit hard-frozen-wall conditional-MAP control, or implement/declare actual revisiting. The ordinary exact incremental arm remains a valid separate strong control; this finding concerns the misleading additional method label, not its replacement.

4. **[P2] Partial posterior checkpoints have no valid-entry mask or complete-online marker.** `tools/e2_revisit.py:91-92` preallocates all parent/repeat/time weights as zero, then lines 175-177 publish the entire arrays after each repeat with only `completed_parent=parent`. After repeat 0, this field already names a parent whose repeat 1 is still zero; future parents are zero too. A downstream reader sees the final four-dimensional schema and full ID vectors but cannot distinguish completed entries from allocated placeholders using an explicit mask. Save a `(parent,repeat,time)` completed mask (or exact completed identities), and publish a terminal online-completion marker before permitting downstream comparison/active-design consumers. Retain partial files for failure evidence but require consumers to reject uncompleted entries.

No claim of global novelty, physical validity, or new scientific gate is made by this review.
