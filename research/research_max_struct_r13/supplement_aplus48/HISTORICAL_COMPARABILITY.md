# 为什么不同轮次会出现不同领先者

首先纠正比较方式：**原R13的A+只在预先指定的机制16子集运行，四个主方法却覆盖48。16对象上的第一名不能直接与其他方法的全48均值对比。** 这次补齐遗漏32，没有重新生成对象、修改原A+参数或按GT选择。全48仍然出现A+的正面结果，不能因为它没有逐例全胜就否定。

同时发现，R13使用的默认A+与R7/R8最终读出存在实际版本差异。本次另外按冻结的R7选项完成同对象版本控制，并补齐NN接口，分别列报。

## 2. “A+”必须注明具体版本

R7最终配置与R8配置打开 `aplus_arc_candidates` 和 `aplus_inherited_gtol`，并采用两轮sweep、1e-8步长停止。实际执行回执有arc/guard计数。R13原runner只将默认 `arm_config` 接到Möbius读出，没有合并这两个选项；原16与本次补32都执行quintic-MM/no-guard分支。

因此本补充保留两列：**A+-MM/R13**、**A+-Arc/R7-readout**。后者只移植R7最终读出选项，仍使用R13物理、current wrapper、预算与选根；不能称复现R7全部实验合同。版本审计有源码和执行计数，参见 `analysis/historical_evidence/APLUS_VERSION_AUDIT.md`。

## 3. NN、current接口和corrector不是一层

完整流水线应注明：训练先验/权重 → 材料初值 → 辅助current或物理双场的初始化 → solver路径 → 物理候选审计 → corrector → 公共选根。

- 同一个NN材料给CIE和DR，不等于相同完整状态。CIE/A+冷current、G19合法物理current投影和DR完整双场具有不同缺陷及约束。当前16对象析因是实际接口比较，未单独识别每个初始化映射的因果效应。
- NN不会因初始Phi较高而被拒绝。它可能提供材料结构却初始拟合较差；应实际运行后续求解。
- raw是proposal阶段按公共Phi保留的物理候选，不必是最后native迭代材料。corrected使用同一原Maxwell目标；primary仍选全部已付费合法候选中的最小Phi。secondary的minR有不同先验语义，不能逐例挑优。
- 原NN训练＋训练/验证数据生成已有402.558889 Mac CPU秒记录（R8 `NEURAL_WARM_STARTS.md:55`）。R13新增16推理准备为1.285002 Mac CPU秒，包含特征/模型加载/写盘，另有最终写回小段不在该计时内。R13未重测旧训练并不意味着它从未记录或免费。不同硬件秒数不直接相加为i9速度。

## 4. 哪些比较可以做

同一轮、同对象、同数据/先验/box、同一候选规则，先看逐例材料图与连续误差，再看同实际CPU前缀和原物理费用。相同最大额度不是相同消费；相同步数不是同成本；跨硬件秒数不能拼速度排名。

同48均值给出当前协议下的整体表现；同16可比较NN、global控制等交集；不同物理数据集保持分组。一个方法救回另一方法的困难对象，是值得研究的增量；不要求所有测试全胜。但不能将新观测、额外训练prior或更多计算带来的效果统称为求解机制优势。

同48跨网格12对象的离散失配未被纯CN噪声球吸收；三维误差、实测标定问题也不能被二维同网格低残差覆盖。当前补充没有新增三维/实测逆解，不借历史图扩大本次优势范围。
