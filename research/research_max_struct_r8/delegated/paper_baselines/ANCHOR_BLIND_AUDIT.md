## Scoring precondition issue: repaired before scoring

Initially `score_warm_starts.py` checked only the anchor seal's status and `tasks==126` before its first private metadata read. That did not independently revalidate the seal's task identities and file stamps, although the separate anchor scorer already did so. This was a concrete protocol verification gap, not observed leakage or a solver defect.

The parent repaired it during this review. Current `score_warm_starts.py:81–91` now checks the frozen identity set, exactly 126 seal entries, and every anchor evidence/output stamp before the first private read at line94. The independent `analyse_anchor_results.py:371–383` constructs the seal only from 126=42×3 terminal matching receipts; its confirmation path verifies stamps and identities again at 386–402. Failed terminal tasks remain represented rather than excluded. No test scoring was run by this reviewer.

## State-dimension concern: excluded after finalization check

The initial RUNNING receipt's placeholder uses 12 sources when config does not specify `public_sources`. This is **not a final-receipt defect**: `run_case.py:226` overwrites it with `model.n*model.ns` in `finally`, and this overwrite exists in the frozen anchor source copy. Three inspected, already-public final receipts for six-source `r8_test_0001` (uniform original A, NN global A+, NN joint global A+) all report3456. No correction to raw receipts or frozen algorithms is needed. The compatibility field counts full current **complex components**, not independent real DOF, as documented in `STATE_AND_COST_SEMANTICS.md`.

## Reproducibility and limits

At review, frozen and current `cie_fft.py`, `run_case.py`, extension config and 126 manifest were byte-equal by direct byte comparison, without hashes. The main scorer change above is a protocol guard, not a numerical algorithm change.

The code matches §3.1's fixed-affine-offset implementation and preserves the stated current/material families and schedule. This audit does not establish actual anchor cost from running receipts, universal descent, material recovery, a basin claim, independent confirmation performance or novelty. Those require the separately sealed executions, complete cost accounting and authorized offline evaluation. No further historical runs or additional scope are proposed.
